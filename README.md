# vibe_coding_hw5_1012
vibe coding做的研究 Meeting 準備儀表板

最終 Vibe Coding Prompt
最後討論完成之後，再把這份完整規格交給 AI：
請依照以下規格製作完整的單頁 Web App。

網站名稱：
Research Meeting Dashboard｜研究 Meeting 準備儀表板

目的：
提供研究生在每週與教授 Meeting 前整理研究進度、確認準備程度、找出優先事項並記錄 Meeting 建議。

請使用原生 HTML、CSS、JavaScript 開發。

重要限制：
1. 所有 HTML、CSS、JavaScript 必須全部包含在單一 index.html。
2. 不使用 React、Vue、Node.js、外部資料庫或任何需要安裝的套件。
3. 網頁需可直接部署至 GitHub Pages。
4. 桌機與手機皆需正常使用。

【功能一：Meeting 基本資料】

包含：
- Meeting 日期
- 研究主題
- 預計報告時間
- 上次教授交代事項

所有資料變更後自動保存。

【功能二：研究事項】

使用者可以自行：
- 新增
- 修改
- 刪除

每筆研究事項包含：
- 事項名稱
- 類別
- 重要程度
- 狀態
- 備註

類別固定為：
資料處理、方法、程式、圖表、結果、文獻、待討論、其他。

重要程度：
高、中、低。

狀態：
已完成、待確認、未完成。

【功能三：Meeting Ready 分數】

重要程度權重：
高=3
中=2
低=1

完成狀態：
已完成=100%
待確認=50%
未完成=0%

計算：

Meeting Ready =
實際取得分數 ÷ 所有事項最高可能分數 × 100%

即時顯示：
- 百分比
- Progress Bar

80～100：
準備完成

50～79：
尚有內容需要確認

0～49：
Meeting 準備不足

【功能四：優先處理】

自動找出：

高重要度＋待確認
或
高重要度＋未完成

的事項。

在 Dashboard 顯示「Meeting 前建議優先處理」。

【功能五：篩選】

可以依：

狀態
重要程度
類別

篩選研究事項。

【功能六：教授可能追問】

加入「模擬教授追問」按鈕。

按下後從預設題庫隨機抽出一題。

至少內建以下問題：

為什麼選擇這個方法？
有沒有其他方法可以比較？
結果是否符合預期？
異常值有沒有檢查原始資料？
有沒有其他資料可以驗證？
文獻中有沒有類似結果？
目前方法有哪些限制？
下一步要怎麼驗證？
這個結果代表什麼？

問題顯示後提供：

「我已準備好」
「加入待辦」

如果按下「加入待辦」，
請自動建立新的研究事項：

「準備回答：＋該問題」

【功能七：Meeting 筆記】

包含：

Meeting 前想問教授
Meeting 後教授建議

Meeting 後教授建議旁加入：

「轉成下次待辦」

按下後將該內容加入研究事項。

【功能八：資料保存】

使用 localStorage。

需要保存：
- Meeting 資訊
- 所有研究事項
- 狀態
- 重要程度
- 備註
- Meeting 筆記

重新整理網頁後所有資料仍需存在。

【功能九：匯出摘要】

加入：

「匯出 Meeting 摘要」

將目前內容整理成純文字檔 meeting_summary.txt。

內容包含：

Meeting 基本資料
已完成事項
待確認事項
未完成事項
Meeting 前問題
教授建議

【功能十：建立新的 Meeting】

提供「建立新的 Meeting」。

按下後先使用確認視窗詢問：

「確定要建立新的 Meeting 嗎？目前資料將會被清除。」

確認後才清除 localStorage 與畫面資料。

【視覺設計】

整體為簡潔、專業、現代的研究工作 Dashboard。

桌機：
兩欄式版面。

手機：
自動變成單欄。

請使用卡片式區塊呈現不同功能。

不同研究事項狀態需要容易辨認，但不要使用過度花俏的動畫。

Progress Bar 更新時可以有平滑動畫。

新增、修改、刪除研究事項後，Meeting Ready、優先事項與統計內容都必須立即同步更新。

請確認：
1. 所有按鈕皆可正常操作。
2. localStorage 正常。
3. 新增、修改、刪除皆正常。
4. 篩選正常。
5. Meeting Ready 計算正確。
6. 教授追問加入待辦正常。
7. 教授建議轉待辦正常。
8. txt 匯出正常。
9. 手機版面正常。
